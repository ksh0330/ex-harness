# 처음 쓰는 사람을 위한 사용 설명

용어를 모두 외울 필요는 없다. **어디에 입력할지 → 무엇을 부탁할지 → 결과를 어떻게 확인할지**만 먼저 익힌다.
이 문서의 화면·출력 예시는 가상이다. 실제 Cofa 화면과 이번 과제 안내를 우선한다.

## 1. 먼저 구분할 여섯 가지

| 화면에서 만나는 말 | 쉬운 뜻 | 내가 할 행동 |
|---|---|---|
| 과제 README | 무엇을 만들고 어떻게 실행·제출하는지 적힌 안내문 | Codex에게 먼저 읽히고 필수 동작을 요약받기 |
| 터미널·Bash | 컴퓨터에 글자로 명령을 내리는 창. Bash는 그 명령을 받는 프로그램 | `pwd`처럼 명령 입력. Codex의 `/status`를 여기에 입력하지 않기 |
| Codex 대화창 | AI에게 할 일을 부탁하고 결과를 받는 곳 | 자연어 요청, `/status`, `$verify` 등을 입력 |
| 파일·폴더·경로 | 문서 / 문서 묶음 / 문서가 있는 위치 | `docs/HANDOFF.md`는 docs 폴더 안 HANDOFF.md 파일이라고 읽기 |
| Browser·미리보기 | 만든 웹 화면을 직접 열어 보는 곳 | 실제로 등록·검색해 결과 확인 |
| 테스트 | 기대한 결과가 나오는지 확인하는 실행 | 명령·기대 결과·실제 결과·실패 여부를 보여 달라고 요청 |

**탭**은 한 화면 안에서 창을 나눠 쓰는 칸이다. Codex용 탭과 계속 실행할 서버용 터미널을 구분한다.
**프로젝트 루트**는 이번 작업의 맨 위 폴더다. Codex에게 “현재 폴더가 과제 루트인지 확인해”라고 요청할 수 있다.

## 2. 전체 과정은 주문 → 제작 → 확인

간단한 예: “수리 요청을 입력하고 나중에 다시 볼 수 있게 한다.”

1. **주문 확인:** README에서 필수 입력·결과·금지 사항을 확인한다.
2. **작게 만들기:** “제목 입력→저장→목록 표시” 한 흐름부터 맡긴다.
3. **컴퓨터 검사:** 빈 제목 거부·정상 저장을 테스트로 확인한다.
4. **내가 직접 확인:** 화면에서 등록하고 새로고침해 데이터가 남는지 본다.
5. **설명 받기:** 어느 파일이 저장하고 왜 그 방식을 골랐는지 묻는다.
6. **남은 문제 기록:** 구현하지 않은 것·확인하지 못한 것·다음 행동을 남긴다.

**완료**는 AI가 자신 있게 말한 상태가 아니다. 요청한 동작과 실제 실행 결과가 맞아야 한다.
테스트가 성공해도 브라우저를 안 눌렀으면 화면 조작은 미확인이다. 문서에 적었다고 기능이 생기지는 않는다.

## 3. 내가 말할 네 문장

### 시작할 때 — Codex 대화창

```text
나는 개발 용어를 거의 모른다. 과제 README와 기존 지침부터 읽어.
내가 만들어야 할 것·만들지 않을 것·확인 방법을 쉬운 말로 설명해.
새 용어는 쉬운 뜻과 지금 내가 할 행동을 붙여줘.
명세가 명확하면 작은 흐름부터 구현하고 실제 결과를 보여줘.
```

### 무슨 말인지 모를 때

```text
방금 설명을 이해하지 못했어.
새 용어 3개 이하로, 실제 입력과 결과 예시 하나로 다시 설명해.
내가 입력할 내용은 입력 위치와 함께 별도 코드 블록으로 보여줘.
실제 실행한 결과와 설명용 가상 예시를 구분해.
```

### AI가 “완료”라고 할 때

```text
무엇을 바꿨고 어떤 명령으로 확인했는지 보여줘.
기대 결과와 실제 결과, 실패·미확인 항목을 짧게 정리해.
내가 직접 눌러볼 순서를 3개 이하로 알려줘.
내가 설명할 수 있도록 핵심 파일·동작 흐름·선택 이유·약점도 풀어줘.
```

### 멈추거나 방향을 바꿀 때

```text
현재 작업을 멈추고 바뀐 파일·실행 상태·실패를 보존해.
지금 가장 중요한 필수 동작 하나와 다음 행동을 정리해.
현재 상태와 다음 명령을 HANDOFF에 남겨. 기존 사용자 변경은 건드리지 마.
```

## 4. 필요한 명령만 — 복사할 부분과 설명 분리

**Bash 터미널:** 현재 폴더 확인.

```bash
pwd
```

가상 출력 `/workspace/task`는 “지금 이 폴더에 있다”는 뜻이다. 실제 위치가 과제 폴더인지 확인한다.

**Codex 대화창:** 현재 모델·작업 위치 등 상태 확인. 항목은 제공 버전에 따라 다르다.

```text
/status
```

**Codex 대화창:** 요청한 동작을 실제 실행 결과와 비교해 달라는 스킬 호출.

```text
$verify
```

스킬이 보이지 않으면 아래 자연어로 대신한다. 설치된 과제에서는 `.agents/skills/verify/SKILL.md`, 하네스 원본에서는 `skills/verify/SKILL.md`를 읽힌다.

```text
요청한 동작을 실제로 실행해 확인하고, 명령·기대 결과·실제 결과·미확인을 정리해.
```

**주의:** 표 안 설명까지 명령 뒤에 붙여 입력하지 않는다. 모르는 명령은 “무엇이 바뀌는 명령인지 먼저 설명해”라고 한다.

## 5. 서버·포트·저장소를 쉬운 말로

| 용어 | 뜻·예시 |
|---|---|
| 서버 | 화면 요청을 받고 처리하는 실행 프로그램. 서버 터미널이 계속 실행 중이어야 웹 화면을 사용할 수 있음 |
| 포트 | 같은 컴퓨터에서 어느 프로그램으로 들어갈지 구분하는 번호. 예: 8000 |
| 0.0.0.0 | 서버가 IDE 밖의 미리보기 연결도 받을 수 있도록 지정하는 주소. Browser에 그대로 넣으라는 뜻은 아님 |
| localhost | 지금 사용하는 컴퓨터를 가리키는 이름. Cofa의 외부 미리보기 주소는 플랫폼 안내를 따름 |
| 프론트엔드 / 백엔드 | 사용자가 보는 화면 / 뒤에서 검사·저장하는 처리 |
| API | 프로그램끼리 요청·결과를 주고받는 약속. 예: 제목을 보내면 접수 번호가 돌아옴 |
| DB·SQLite | 나중에 다시 읽을 데이터를 저장하는 곳 / 이 예제에서 쓰는 파일 기반 저장 방식 |
| JSON / CSV | 이름·값으로 정보를 담는 형식 / 표를 텍스트로 담는 형식. 실제 과제의 입력 형식을 따름 |
| 저장소(repo) | 코드·문서·변경 기록을 모아 둔 공간 |
| 원격 / 로컬 | GitHub 같은 다른 곳 / 현재 작업하는 컴퓨터·폴더 |
| 브랜치·main | 변경 기록을 이어가는 작업 줄기 / 이 저장소의 기본 줄기 이름 |
| clone | 원격 저장소를 현재 환경에 내려받기. 하네스 설치·앱 실행과는 다른 작업 |
| commit | 변경한 파일을 로컬 Git 기록으로 남기기. 일반 파일 저장과 별도 |
| push | 로컬 커밋을 원격으로 전송. 시험에서는 금지 |
| diff | 수정 전후의 차이. 요청하지 않은 변경이 섞였는지 확인할 때 사용 |
| SHA·커밋 해시 | 특정 변경 기록을 가리키는 식별자. 짧은 `63550bc` 같은 표기. 비밀번호가 아님 |

실행 오류 예시: “포트가 이미 사용 중”이면 같은 번호를 다른 프로그램이 쓰고 있다는 뜻이다. 기존 서버가 무엇인지 먼저 확인하고 임의로 종료하지 않는다.
`--port 8000`의 `--port` 같은 **옵션**은 명령의 동작을 정하는 추가 정보다. 모르면 Codex에게 뜻과 영향을 설명받는다.

## 6. AI 작업 용어는 행동으로 읽기

| 말 | 실제로 할 행동 |
|---|---|
| FDE | 현장의 문제를 파악하고 구현·검증·인계까지 연결하는 역할. 내가 문제와 결과를 감독 |
| 하네스 | AI 작업용 도구 상자. 설치 자체가 시험 과제 구현은 아님 |
| P1~P7 | 탐색·범위·골격·구현·검증·보강·전달을 기록하는 이름. 강제로 일곱 번 승인받는 절차가 아님 |
| 수용 기준 | “다시 열어도 저장된 요청이 보인다”처럼 성공 여부를 확인할 문장 정하기 |
| Slice·E2E | 입력부터 결과까지 작은 흐름 하나를 끝까지 확인하기 |
| 어댑터·스키마 | 외부 입력을 내부 형식으로 바꾸는 부분 / 어떤 이름·형식의 값을 받을지 정한 규칙 |
| 결정론 코어 | 같은 입력에 같은 판정을 내리는 고정 코드. 저장·권한 판단을 AI 답변에 맡기지 않기 |
| 원자성·롤백 | 한 묶음이 전부 반영되거나 전부 취소됨 / 실패하면 이번 변경을 취소. CSV 중간 오류로 일부만 저장되지 않는지 확인 |
| 회귀 테스트 | 수정한 기능뿐 아니라 영향받는 기존 기능도 계속 동작하는지 확인 |
| Mock | 실제 외부 서비스 대신 쓰는 가짜 연결. 실제 서비스와 연결했다고 주장하지 않기 |
| Handoff | 어디까지 했고 무엇이 실패했으며 다음에 무엇을 할지 적어 이어받게 하기 |
| Context·Compact·Resume | 대화 문맥 / 요약 / 저장 대화 재개. 파일·실행 중 서버를 대신 보존하거나 복구하는 것은 아님 |
| Review | 실제 변경에서 오류·누락을 찾아보기. 검토 지적도 코드·재현으로 판단 |

MCP·Plugin·Hook·Subagent는 지금 외울 필요 없다. 필요해졌을 때 “효과·비용·권한·대안”을 설명받고 선택한다.

## 7. 09시에는 확인하고 나서 결정

사전 테스트는 환경에서 실제로 막히는 부분을 찾는 시간이다. 그때 얻는 정보는 다음 여섯 가지다.

1. 어떤 도구·모델·자료 사용이 허용되는가?
2. README와 파일은 어디에 있는가?
3. 제공 Codex와 필요한 명령이 실행되는가?
4. 설치가 필요한가, 직접 지시만으로 충분한가?
5. 실제 서버·미리보기·테스트가 동작하는가?
6. 본시험에서 환경이 초기화되면 무엇을 다시 해야 하는가?

문제가 없으면 현재 버전을 유지한다. 문제가 있으면 **증상→관련 파일→작은 수정→관련 검증** 순으로 진행한다.
현장 결과를 받기 전에는 Cofa 호환성을 확인했다고 기록하지 않는다. 본시험 과제·코드·로그는 외부로 전송하지 않는다.
상세한 문제별 수정 위치는 [MORNING](MORNING.md)의 6번을 참고한다.

## 8. 새 PC의 Codex 새 대화에 넣을 프롬프트 한 개

새 과제 폴더에서 시작할 때는 [빠른 시작](QUICKSTART.md)의 현재 명령을 따른다. 아래는 **이 하네스 저장소가 열린 준비용 Codex 대화**에 넣는 별도 프롬프트다. 다른 PC에서도 쓸 수 있도록 기존 PC의 D: 경로를 적지 않는다.

```text
현재 열린 ex-harness 저장소의 AGENTS.md, docs/BASICS.md,
docs/MORNING.md, docs/HANDOFF.md를 읽고 git status부터 확인해.
나는 개발 용어를 거의 모른다. 지금 할 일 3개와 그 이유부터 쉬운 말로 설명해.
새 용어는 뜻·구체적인 예·내가 할 행동을 붙여줘.
입력 위치와 복사할 명령은 분리하고, 실제 결과와 가상 예시를 구분해.
모르는 부분은 설명부터 하고, 관찰된 문제가 있을 때만 관련 파일을 수정·검증해.
기존 변경을 보존하고 시험 제한·외부 전송 금지를 지켜.
```

이번 학습의 목표는 “용어를 외웠다”가 아니라 **명령을 어디에 넣을지 알고, 결과를 확인하고, 모르는 지점에서 멈춰 질문할 수 있는 것**이다.
