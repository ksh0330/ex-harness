# 시험 직전 빠른 시작

먼저 과제 안내를 읽는다. 설치는 선택 사항이다. 지침과 예제를 과제에 맞지 않게 강제하지 않는다.
기능을 고르기 어렵다면 [매뉴얼 4절: 상황별 추천·선택·비추천](MANUAL.md#4-도구를-언제-선택하는가), 대화 유지·압축·재개·Fork는 [6절](MANUAL.md#6-중단수정재개컨텍스트)을 본다. 명령 지원 근거와 로컬·Cofa 미검증 구분은 매뉴얼 2절에 있다.
학습 시간이 부족하면 [MORNING](MORNING.md)의 08시 요약과 09시 여섯 항목만 확인한다. 긴 모의시험은 선택이다.
용어가 대부분 낯설면 [BASICS](BASICS.md)의 입력창 구분·전체 흐름·질문 문장부터 읽는다.
이 일정은 사용자가 제공한 2026-10-31 10:00~14:00, 과제 최대 180분·후속 6×5분 기준의 연습안이다. 실제 타이머와 제출 안내가 우선이다.

## 09:00 사전 체험 체크리스트

아직 직접 실행하지 않은 항목은 체크하지 않는다. Cofa 내부의 허용된 합성 연습 자료만 사용하며 개인 파일을 올리지 않는다.

- [ ] 과제 안내·금지 행위·사용 가능 모델·실제 시작/종료/제출 절차 확인
- [ ] Bash와 Codex 입력창을 구분한다. Bash에서 `pwd`, `git status --short`, `codex --version`을 읽기만 실행
- [ ] `codex`로 시작, `/status`에서 폴더·모델·컨텍스트 확인, `/` 목록 확인
- [ ] `/model`에서 허용된 Sol 6.1(있으면)을 선택하고 상태 확인. 없으면 제공 목록 안에서 선택
- [ ] 기존 README·AGENTS·프로젝트 스택·서버 명령 확인. 임의 업데이트·권한 변경 안 함
- [ ] 설치가 필요하고 공개 자료 사용이 허용됐는지 확인. preview 후 필요한 경우만 apply
- [ ] `/skills` 또는 `$`로 스킬 확인. 없으면 SKILL.md 직접 읽기
- [ ] 합성 예제를 사용할 수 있는 경우 웹 등록·검색·상태 변경·새로고침, 실제 포트 미리보기 확인
- [ ] 관련 테스트 실행·실패 출력·Git diff 확인, AI에게 오류 원인 설명시키기
- [ ] 중단 → 변경 범위 축소 → 관련 테스트 → 재개를 한 번 수행
- [ ] Handoff 저장 후 현재 세션 유지, compact 또는 resume 경로를 한 번 확인
- [ ] 구조와 약점을 자기 말로 설명. 미확인 항목은 남기고 시험 전 불필요한 설정 작업 중단

## 설치가 필요할 때만

과제 폴더 Bash에서 다음을 각각 실행한다. 이미 `/tmp/ex-harness`가 있으면 clone을 반복하지 말고 내용을 확인한다.

```bash
git clone https://github.com/ksh0330/ex-harness /tmp/ex-harness
bash /tmp/ex-harness/install.sh
bash /tmp/ex-harness/install.sh --apply
```

첫 설치 실행은 PLAN과 `created=0; mode=preview`. apply는 없는 파일만 CREATE한다.
기존 AGENTS·스킬·docs·Git 설정은 보존한다. 자동 업데이트는 없다.
Python 실행명이 `python3`뿐이면 설치기는 자동 선택한다. 예제 명령의 `python`도 `python3`로 바꾼다.
Windows 사전 준비에서는 `python D:\ex-harness\tools\install.py --target 연습폴더`로 preview, 뒤에 `--apply`로 적용한다.
원본 저장소 내부에는 설치하지 않는다. 예제가 필요할 때만 `--with-examples`를 추가하고 대상의 `.harness/kit`에서 실행한다.

기존 AGENTS가 있거나 설치하지 않은 경우 Codex 입력창:

```text
과제 README·AGENTS.md와 관련 진입점·git status를 먼저 확인해.
수용 기준을 관찰 가능한 동작으로 정하고 가장 작은 흐름부터 구현·관련 검증해.
모호한 사항만 질문하고 기존 파일·설정과 사용자 변경을 보존해.
완료 주장에 실행 증거를 붙여. 시험 제한과 외부 전송 금지를 지켜.
```

보조 지침이 설치됐다면 `.harness/AGENTS.md도 읽어`를 덧붙인다.
clone이 1분 이상 막히면 위 직접 지시로 진행한다. 보안·네트워크 우회나 런타임 설치로 시간을 쓰지 않는다.
스킬 미인식 시 `.agents/skills/build-slice/SKILL.md를 읽고 수행해`를 사용한다. 충돌한 스킬은 원본 `/tmp/ex-harness/skills/.../SKILL.md`를 읽는다.

## 180분 예산 예시

| 경과 | PM의 결정 | Codex의 산출물 |
|---|---|---|
| 0~15분 | README·제약, 질문이 필요한지 | 사실/가정, 최소 필수 기준 |
| 15~30분 | 핵심 흐름과 제외 범위 | 짧은 계획·기존 코드 영향 |
| 30~110분 | 실행 화면·입출력 확인 | 흐름별 구현·관련 테스트 |
| 110~140분 | 부족한 필수 기준 우선 | 위험 경로·회귀 보강 |
| 140~165분 | 기능 동결·약점 수용 | 핵심 전체 검증·실행법·최종 인계 |
| 165~180분 | 실제 제출 절차 확인·완료 | 저장·필수 파일·증거 확인 |

고정 벽시계 시각으로 밀지 않는다. 실제 타이머가 줄면 선택 기능·추가 에이전트·꾸밈을 먼저 제외한다.
후속 서술형에서는 AI 사용 금지라는 사용자 안내를 따른다. 과제 종료와 후속 전환·제출 확정은 현장 안내로 확인한다.

| 위치 | 명령·입력 | 목적 |

| Bash | `git status --short`, `git diff` | 현재 변경과 사용자 작업 확인 |
| Bash | `codex`, `codex resume` | 시작·저장 세션 선택 |
| Codex | `/status`, `/model`, `/skills` | 상태·허용 모델·스킬 |

| 서버 Bash | 프로젝트 README의 서버 명령 | `0.0.0.0`·실제 포트 확인, 별도 터미널 유지 |

각 명령의 가상 출력·오류 대응은 [MANUAL](MANUAL.md), 지원 경계는 [SOURCES](SOURCES.md)를 참고한다.
