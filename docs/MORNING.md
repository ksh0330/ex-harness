## 4. 명령은 입력 위치를 먼저 본다

### Bash 터미널에서

한 줄씩 실행한다. 예제 앞에 보이는 `$` 프롬프트는 입력하지 않는다.

```bash
pwd
git status --short
git diff
codex --version
codex
```

`pwd`는 현재 폴더, `status`는 변경 파일, `diff`는 수정 내용이다. 원래 사용자 변경을 구분한다.
`git diff`는 새 미추적 파일을 보여주지 않을 수 있으므로 status도 본다.
`codex`를 실행한 뒤에는 아래 대화 명령을 넣는다.

### Codex 대화 입력창에서

아래는 한 번에 붙여넣는 스크립트가 아니라 각각의 선택 명령이다. 제공 버전의 `/` 목록부터 확인한다.

```text
/status       모델·폴더·문맥 확인
/model        허용된 모델 목록·추론 강도 확인
/skills       스킬 목록
/review       변경 검토
/compact      긴 대화 요약
$build-slice  작은 흐름 구현
$verify       실행 증거와 기준 대조
$handoff      현재 상태·다음 행동 기록
```

실제 입력은 `/status`처럼 명령 부분만 친다. `$verify`의 `$`는 스킬 호출의 일부다.
작은 수정은 자연어+해당 부분 확인, 낯선 구현은 discover→범위 결정→build-slice, 제출은 verify를 우선한다. 모든 Skill을 돌리지 않는다. [매뉴얼 4절](MANUAL.md#4-도구를-언제-선택하는가)의 상황별 선택과 [6절](MANUAL.md#6-중단수정재개컨텍스트)의 유지·압축·재개·Fork 표를 참고한다. `/mcp`·`/hooks`는 확인 기능과 설정 변경을 구분하며 시험 중 새 연결·활성화는 하지 않는다.
스킬이 없으면 `.agents/skills/verify/SKILL.md를 읽고 수행해`라고 쓴다. 충돌한 스킬은 기존 것이 보존되므로 원본 하네스의 skills 경로를 직접 읽는다.

기본 키: Enter는 입력 전송, 위쪽 화살표는 이전 입력, Ctrl+R은 Bash에서 이전 명령 검색이다. Codex에서도 현재 문서상 입력 이력 검색을 지원하나 현장 버전에서 확인한다.
작업 중단은 Codex 화면의 중단 키·Esc 안내를 따른다. 서버 터미널의 Ctrl+C는 서버를 끈다.
웹 IDE 단축키를 Codex desktop 단축키와 같다고 가정하지 않는다.
공식 명령 근거: [OpenAI Developer commands](https://learn.chatgpt.com/docs/developer-commands). 공식 지원과 Cofa 실제 제공은 구분한다.

## 6. 현장 관찰 뒤 무엇을 수정할까

**현장에서 관찰한 실패가 수정의 출발점이다.** 추측으로 환경 호환 코드를 추가하지 않는다.
사전 테스트가 끝나고 본시험 환경이 초기화된다면 필요한 지침만 다시 적용한다. 원격 준비 저장소의 변경이 이미 clone한 폴더에 자동 반영되지는 않는다.

| 현장 관찰 | 조치·수정 위치 | 확인할 증거 |
|---|---|---|
| README에 문제·해법·출력이 이미 명확 | 질문은 빠진 경계만. discover/agreement는 필요한 만큼만 | 필수 기준을 구현·테스트와 대조 |
| 명령·모델이 문서와 다름 | 현장 목록 사용. 필요 시 docs/MORNING·QUICKSTART·SOURCES의 일반 안내만 보정 | `/`·help·허용 목록. 모델명 추정 금지 |
| Python이 없거나 3.10 미만 | 설치 생략·직접 지시, 기존 스택 사용. 반복 가능한 prep 결함이 확인될 때만 tools/install.py·install.sh 보정 | preview·보존 테스트. 현장에서 런타임 설치하지 않음 |
| AGENTS·스킬이 이미 있음/안 보임 | 기존 파일 보존. 보조 지침·원본 SKILL.md 직접 읽기 | git diff와 관련 파일. 강제 덮어쓰기 안 함 |
| 서버는 되는데 Browser 안 됨 | 바인딩·출력 포트·경로·플랫폼 전달부터 확인. 앱 서버 진입점·실행 문서만 필요한 만큼 수정 | /health와 실제 페이지. HTTP만 확인했으면 UI는 미검증 |
| 실제 과제의 상태/컬럼/규칙이 예제와 다름 | 대상 앱의 입력 어댑터·관련 검증 수정. 규칙이 여러 경로에 공통일 때만 코어 변경 | 신규·기존 입력, 실패 원자성·회귀 테스트 |
| AI가 동작을 만들었는데 내가 설명 못함 | 기능 확대를 멈추고 핵심 파일·흐름·선택 이유·테스트·약점 5줄 요청 | 실제 코드와 설명 일치. 미확인을 채우지 않음 |

준비용 공통 수정은 이 저장소에서 검증 후 반영할 수 있다. **본시험의 과제·코드·환경 로그·결과물은 Notion·GitHub·외부 Codex로 보내지 않는다.** 본시험 수정은 제공 Cofa 안에서 한다.
현재 실증된 런타임 결함은 없어 앱 코어를 추가 개편하지 않았다. 이번 개정은 짧은 학습 경로·인지 점검·설치 가이드다.

```text
현재 열린 ex-harness의 AGENTS.md, docs/BASICS.md,
docs/MORNING.md, docs/HANDOFF.md를 읽고 git status부터 확인해.
나는 개발 용어를 거의 모른다. 지금 할 일 3개와 이유부터 쉽게 설명해.
새 용어는 뜻·예·내가 할 행동을 붙이고 입력 위치와 명령을 분리해.
설명부터 하고, 관찰된 문제가 있을 때만 관련 파일을 수정·검증해.
기존 변경을 보존하고 시험 제한·외부 전송 금지를 지켜.
```

### 실제 과제 시작: Cofa의 제공 Codex에만

```text
과제 README·안내·기존 AGENTS·관련 진입점·git status부터 확인해.
필수 동작, 제약, 제외 범위, 검증 명령을 짧게 정리해.
명세가 명확하면 불필요한 인터뷰를 하지 말고 빠진 경계만 질문해.
작은 흐름부터 구현·관련 검증하고, 핵심 흐름마다 파일·선택 이유·증거·한계를 짧게 설명해.
기존 파일을 보존하고 현장 금지 행위를 하지 마.
```

하네스가 설치됐다면 `.harness/AGENTS.md를 보조 지침으로 읽어`를 덧붙인다.

### 방향을 바꾸거나 시간이 부족할 때: Cofa 안에서

```text
현재 작업을 멈추고 diff·실행 상태·실패를 보존해.
남은 필수 조건과 실제 남은 시간에 맞춰 선택 기능을 줄여.
영향받는 코드만 수정하고 관련 검증 뒤 재개해. 사용자 변경은 건드리지 마.
```

### 이해·인계가 필요할 때: Cofa 안에서

```text
내 실제 구현 기준으로 핵심 파일, 데이터 흐름, 선택 이유, 실행 증거, 약점·다음 검증을 5줄로 설명해.
확인하지 않은 내용을 채우지 마. docs/HANDOFF.md에 현재 상태와 다음 명령을 남겨.
인계 때문에 실패 코드를 커밋하거나 세션을 자동 교체하지 마.
```

후속 서술형이 시작되면 AI를 사용하지 않는다. 답은 **내 결정→코드 근거→실제 검증→약점·위험·다음 확인**으로 짧게 쓴다.
질문 전제가 실제 코드와 다르면 차이부터 말한다. 예제의 결정을 내 시험 결과의 결정처럼 외우지 않는다.
