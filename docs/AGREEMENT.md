# 작업 범위와 수용 기준

## 근거와 권한

사용자가 첨부한 「범용 AI Native FDE 하네스 설계, 구현, 검증 및 Cofa 실전 준비」 요청이 기준이다.
기존 헌장의 인터뷰·사전 승인·세션 교체 강제와 충돌하는 부분은 이번 요청의 자율 실행·상황별 절차를 적용한다.
이 문서는 실무자 인터뷰를 했다는 기록이 아니다. 외부 전송은 명시적으로 허용된 사전 준비용 공개 저장소의 검증된 일반 코드·문서 push에 한정한다. 시험 데이터는 다루지 않는다.

## 해결할 문제와 3 why

- 문제: 기존 하네스는 고정 시험 절차만 제공하며 파일 보존과 재사용성을 실행으로 입증하지 못한다.
- 데이터: 기존 저장소와 Git 기록, 공식 문서, 합성 예제만 사용한다. 실제 고객·시험 데이터 없음.
- 비용: 강제 인터뷰·인계·승인과 설치 시 덮어쓰기가 제한 시간과 기존 프로젝트를 손상시킨다. 현재 소요 시간·절감률은 미측정.
- 유지: 저장소 소유자가 표준 라이브러리 코드·테스트와 결정 기록으로 관리한다. 기능 변경 시 관련 테스트, 릴리스 시 전체 테스트를 실행한다.

## 범위

필수: 얇은 운영 지침, 선택형 스킬 8개 정비, 보존형 설치기, 의존성 없는 Python 공통 모듈, 합성 웹·배치 예제, 매뉴얼·도메인 적용·모의시험·인계.
선택 기능은 가이드로만 제공: MCP·Hook·Plugin·Subagent. 설치·외부 연결·설정 변경은 기본 없음.
제외: 완성형 범용 제품, 인증/RBAC 구현, 실제 외부 API·LLM 호출, 실제 시험 답안 추정, Cofa 검증 주장, 사용자의 학습 완료 대리 판정.

## 종료 조건과 위험

필수 코드의 테스트와 문서 검토를 마치면 설계 반복을 종료한다. 실패·미검증은 남긴다.
Python 또는 Bash가 없으면 설치 대신 짧은 직접 지시로 운영한다. 기존 기술 스택을 Python으로 교체하지 않는다.
예제 서버는 로컬 연습용이며 인증이 없다. 배포·규제 준수는 별도 설계다. 범용 템플릿이 규제 준수를 보장하지 않는다.
