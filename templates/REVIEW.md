# Builder / Reviewer 운영

Builder는 메인 세션에서 분석·설계·구현·테스트·UI/UX·최종 검증을 계속 담당한다. Reviewer는 읽기 전용으로 감사하고 결과를 Builder에 전달한다. 같은 파일을 동시에 수정하지 않는다. 리뷰를 위해 매 단계 새 세션을 만들지 않으며, 앞선 검토 이후의 변경·미해결 위험만 다시 본다.

| 체크포인트 | 감사 범위 |
|---|---|
| P2 종료 | README 요구 누락·제출 조건·설계/데이터 구조·역할·검증 가능한 기준 |
| P4 종료 | 필수 기능·핵심 실행·알고리즘 제약·인증/권한 |
| P5~P6 | 보안·오류 처리·데이터 정합성·테스트 공백·성능 근거·UI/UX/반응형 |
| P7 | README/실행 일치·필수 파일/크기·최종 보고서·미검증·사용자 제출 사항 |

작은 수정에는 관련 항목만 적용한다. 마감이 촉박하면 필수 위험과 제출 보존에 집중하며 생략한 검토는 미검증으로 기록한다.

## 지원과 허용부터 확인

1. 제공 도구 목록과 읽기 전용 `codex --version`, `codex --help`, 필요한 경우 `codex review --help`로 실제 기능을 확인한다. 도움말 존재는 실행 성공·독립성·현장 허용의 증거가 아니다.
2. 현장 규정에서 별도 에이전트/검토·모델 사용이 허용됐는지 확인한다. 불명확하면 설정을 켜거나 우회하지 않고 현재 세션 순차 감사로 진행한다. 모델은 제공 목록의 허용 모델만 사용한다.
3. 지원·허용이 모두 확인되면 제공 Subagent 또는 독립 검토 기능에 필요한 요청·기준·기준 커밋/변경 파일·테스트만 전달한다. 독립성이 목적이면 Builder의 기대 결론을 주입하지 않는다. Reviewer에는 파일/설정 수정·커밋·외부 전송 금지를 명시한다. 검증용 임시 합성 데이터만 허용한다.
4. 불가하면 현재 세션에서 `cross-review`를 직접 적용한다. 목록에 없으면 `.agents/skills/cross-review/SKILL.md`, 충돌하면 원본 `skills/cross-review/SKILL.md`를 읽는다. 기록에 **현재 세션 순차 감사, 독립 검증 아님**이라고 적는다.

## 별도 세션이 필요한 경우만

먼저 handoff로 `docs/HANDOFF.md`(또는 실제 지정 경로)에 기준 커밋·검토 대상·테스트·미해결·수정 금지 파일을 저장한다. Builder는 검토 대상 파일 편집을 잠시 멈춘다. 새 터미널은 **같은 과제 README 폴더**에서 열고 다음을 입력한다:

```sh
codex
```

새 Codex에서 `/model` 또는 제공 선택 화면으로 현장 허용 모델을 선택한다. 아래 프롬프트는 handoff 경로가 다르면 실제 경로로 바꿔 제공한다:

```text
읽기 전용 Reviewer로 검토해. 과제 README와 AGENTS.md, docs/HANDOFF.md, docs/STATUS.md를 읽고 Git 상태·기준 커밋·검토 대상을 확인해. 파일·설정 수정, 커밋, 외부 전송은 하지 마. 요구 누락·설계/데이터·필수 기능·알고리즘 제약·권한/보안·오류/테스트·UI·제출물 중 현재 체크포인트의 관련 항목을 감사하고, 심각도·파일:줄·재현 조건·영향·검증 근거·수정 방향으로 보고해. 확인 못한 부분과 지적 없음도 명시해. 결과는 채팅에만 출력해.
```

사용자가 리뷰 결과를 메인 채팅에 붙여넣거나 IDE에서 Markdown으로 저장하고 그 파일을 읽힌다. 세션 간 자동 공유를 가정하지 않는다. 실제 도구가 결과를 메인에 반환하면 그 전달 경로를 사용한다. 세션 생성·전환을 몰래 수행하거나 기존 세션을 종료하지 않는다.

## 결과와 후속 처리

현재 STATUS/DECISIONS 또는 과제 지정 기록을 재사용한다. 각 발견에 ID, 리뷰 모드/주체, 기준 커밋·대상 diff, 심각도·근거, Builder의 반영/보류/거절·이유, 수정 파일/커밋·새 테스트 결과를 연결한다. 이것을 사용자 수락으로 표기하지 않는다. 요구를 바꾸는 판단만 사용자에게 짧게 묻는다.

Reviewer가 보고한 사실을 Builder가 검증하고 수정한다. 수정 관련 검증 후 중요한 미해결만 재검토한다. 리뷰 통과가 브라우저 관찰·현장 실행·최종 사용자 수용을 대신하지 않는다. Hook 없이 phase-gate가 이 절차를 운영한다.
