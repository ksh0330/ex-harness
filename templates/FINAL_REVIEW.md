# 최종 설명 보고서

작성 규칙: 과제 지정 보고서가 있으면 그 문서에 통합한다. 없으면 `docs/FINAL_REVIEW.md`에 작성한다. 이 템플릿은 빈 형식이며 실제 결과가 아니다. 코딩 단계 종료 전에 verify로 근거를 확인하고 wrapup으로 작성·설명한다. 후속 서술형(문항당 5분·AI/복사 붙여넣기 금지)에서는 AI를 쓰거나 보고서를 답변에 자동 입력하지 않는다.

각 항목은 **핵심 결론 → 코드/기록 근거 → 선택 이유 → 검증 결과 → 한계** 순서로 짧게 적는다. 코드 근거는 실제 파일:줄 또는 함수/테스트 이름과 커밋으로 연결한다. 실행하지 않은 결과는 미검증이다. AI 제안/추정과 사용자 실제 수락·거절·수정·미응답은 별도 표시한다. 해당 없는 항목은 이유를 적고 기능을 꾸며내지 않는다.

## 1페이지 요약

- 목표/필수 요구와 완료·부분·미완료:
- 구조/조회→처리→저장 흐름, 주요 모듈:
- 알고리즘/저장 선택 이유와 가장 중요한 한계:
- 실제 사용자 결정과 AI 제안 중 중요한 것:
- 실행 검증/실패 후 수정/Reviewer 결과:
- 브라우저 핵심 흐름·새로고침·오류·좁은 화면 관찰 또는 미검증:
- 보안/데이터 위험·미완료·추가 시간의 첫 개선:
- 최종 코드 커밋/미커밋, 제출 파일 목록/실제 크기, 사용자 확인·제출:

요약은 한 화면 또는 출력 1페이지 수준으로 줄이고, 세부 근거는 아래에 둔다. 최종 Git/파일 크기 확인이 작성 후라면 확인 시점·대상 커밋을 밝혀 순환된 완료 주장을 피한다.

## 제출 직전 사용자 안내

필수 충족 / 실제 테스트 및 브라우저 결과 / 최종 Git 커밋·미커밋 / 제출 파일·총크기 / 보안·알고리즘 위험 / 보고서 위치 / 직접 확인·최종 제출 행동을 짧게 전달한다. 실제로 측정한 범위와 시점을 적는다. 민감 파일·하네스 원본/내부 .git·대용량 의존성 포함 여부도 지정 제출 방식으로 확인한다. 파일 삭제·최종 제출은 자동 수행하지 않는다.
