name: cross-review
description: 요청받은 검토 또는 큰 변경의 P5/P6에서 유용한 추가 검토를 읽기 전용으로 수행해 근거 있는 결함을 보고한다. 별도 세션은 선택 사항이다.
---

리뷰 전용이다. 파일·설정 수정, 커밋, 외부 전송은 하지 않는다.
검증용 임시 폴더·캐시는 허용하되 추적 파일·실제 데이터는 변경하지 않는다. snapshot 갱신 등 작업 파일을 바꾸는 검증은 실행하지 않는다.
독립 리뷰 환경이 없으면 현재 세션에서 수행하되 독립 검증으로 표시하지 않는다.
P2/P4/P5~P6/P7 체크포인트의 지원 확인·감사 범위·별도 세션 프롬프트·결과 전달은 `.harness/templates/REVIEW.md` 또는 원본 `templates/REVIEW.md`를 필요할 때 읽는다. 도움말 존재를 실행 성공이나 현장 허용으로 간주하지 않는다. 별도 세션은 handoff로 상태를 보존한 뒤 사용자가 열며, 제공 Subagent는 실제 지원·허용 범위에서만 호출한다.
합의문: 요청과 범위·제약의 일치, 관찰 가능한 기준, 만들어낸 수치·확인 여부를 검토한다.
코드: 실제 실행 경로의 오류·입력 검증·권한·저장 경계·회귀·문서 불일치를 우선한다.
필요한 파일과 관련 검증만 읽거나 실행한다. 실제 데이터·외부 시스템을 바꾸는 검증은 하지 않는다.

근거 있는 지적만 심각도순으로 보고한다.
| 심각도 | 파일:줄 | 재현 조건·문제 | 영향 | 수정 방향 |
|---|---|---|---|---|
문제가 없으면 “확인한 범위에서 지적 없음”과 확인 범위·미검증을 쓴다. 정해진 개수를 채우려 지적을 만들지 않는다.
보고에는 검토 모드/주체·기준 커밋과 대상 diff·발견 ID를 붙인다. Builder가 수정·보류·거절 이유와 수정 커밋·새 검증을 기록하고, 중요한 미해결만 재검토한다. Reviewer 발견을 사용자 수락/거절로 바꾸지 않는다.
완료: 지적을 재현 조건·파일·실행 근거에 연결했으면 메인 작업으로 전달한다. 별도 세션이 실제 허용되고 유리한 경우에만 터미널의 `codex`, 읽을 파일·수정 금지 범위, 결과를 Markdown으로 메인에 전달할 방법을 안내한다. 새 채팅은 읽기 전용 지시와 허용 모델 선택이 필요하며 자동 공유를 가정하지 않는다.
