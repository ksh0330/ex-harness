---

STATUS, 요청/AGREEMENT, 관련 diff와 최근 커밋을 읽는다.
- 드리프트: 요청 밖 기능·설정 변경·과도한 추상화가 생겼는가?
- 증거 없는 완료: 완료 주장을 실제 테스트·실행과 연결할 수 있는가?
- 너무 순조로움: 정상 경로만 봤거나, 실패·제약·가정이 숨겨졌는가?

경과 시간이 주어진 경우에만 남은 일과 비교한다. 진척률·시간·성과를 꾸미지 않는다.
문제가 있으면 영향 범위와 해결 순서를 정하고 권한 내에서 조치한다.
상태와 미검증을 STATUS에 기록한다. 작은 수정마다 단계를 만들지 않는다.
큰 작업의 P1~P7 전환에는 실제 완료 / 새로 실행한 테스트·종료 코드 / 미완료 / 중요 결정 / 변경 파일·Git 상태 / 로컬 커밋 가능 여부 / 다음 단계 조건을 짧게 남긴다.
현장 Git 허용·사용자 금지 없음·의미 있는 검증 산출물이 있으면 P1~P3에서도 이번 파일만 명시적으로 stage해 `[P단계] 내용`으로 로컬 커밋한다. 사용자 변경·실패 코드·빈 커밋은 제외한다. Git 저장소가 없으면 init 전에 질문한다. identity 수정·push는 하지 않는다.
P2/P5 종료가 세션 교체를 뜻하지 않는다. 인계가 유용하면 실제 상태를 보존하고 현재 세션 지속·compact·resume 중 선택한다.
