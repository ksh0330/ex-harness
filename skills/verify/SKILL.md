주장을 증명할 명령을 고르고 지금 실행한다. 전체 출력·종료 코드·skip을 확인한다.
문구/UI는 해당 부분, 함수는 관련 테스트, API·DB·인증·공통 모듈은 영향 경로, 큰 구조 변경·최종 전달은 핵심 전체를 확인한다.
매번 전체 테스트를 반복하지 않는다. 긴 서버는 사용자에게 실행 명령을 주고 직접 확인할 항목을 적는다.
자동 테스트 서버는 테스트 중 열고 반드시 닫는다.

| 기준 | 충족/부분/미충족/미검증 | 명령·결과·테스트 이름·파일:줄 |
|---|---|---|

변경에 관련된 빈 입력·잘못된 형식·경계·보안·문서 일치를 확인한다.
인증/역할별 권한 거부·중복·저장 후 조회/재시작은 구현된 위험 경로에 적용한다. 인증 없는 로컬 도구에 임의 인증 스택을 추가하지 말고 적용 제외 근거를 적는다.
Mock·로컬·실제 연동·Cofa 검증은 별도로 표시한다. 과거 결과를 현재 실행으로 포장하지 않는다.
권한 범위의 결함은 고치고 관련 검증을 다시 실행한다. 범위 밖 조치만 질문한다.
큰 작업은 STATUS에 결과와 남은 위험을 기록한다. 테스트 성공은 사용자 수용·학습 완료를 뜻하지 않는다.
완료: 각 필수 기준의 현재 결과와 실패·skip·미검증·남은 위험을 구분해 보고한다. 미검증을 통과로 바꾸지 않으며 필수 실패가 남으면 수정 또는 제한 보고로 이어간다.

P6 보강에서는 기준 알고리즘과 대안의 정확성·경계·복잡도를 같은 입력으로 비교하고 가능하면 실제 성능을 측정한다. 기준·입력 크기·명령·결과·미측정을 구분한다. 차이 없는 최적화나 요구 밖 재구현은 추가하지 않는다.
웹 UI는 제공 미리보기에서 입력→처리→저장→새로고침, 오류 메시지·좁은 화면을 실제 확인한다. 직접 조작이 불가능하면 사용자가 입력할 주소/실제 포트·행동·기대 결과를 안내하고 답변 전 UI 미검증으로 남긴다. API 성공을 UI 조작 성공으로 대체하지 않는다. Computer Use·외부 연결을 활성화하지 않는다. UI 없는 과제는 해당 없음이다.
