# 판정 관문 (모든 주장 전에)
1. 이 주장을 증명하는 명령이 무엇인지 정한다.
2. 그 명령을 지금 새로 전부 실행한다. 이전 실행 결과는 증거가 아니다.
3. 출력 전체와 종료 코드를 읽고 실패 개수를 센다.
4. 출력이 주장을 뒷받침할 때만 주장한다. 아니면 실제 상태를 그대로 보고한다.

# 절차
1. docs/AGREEMENT.md의 성공 기준과 P0 목록을 읽는다.
2. 테스트 전체를 실행한다. 없거나 부족하면 성공 기준 측정에 필요한 테스트를 최소로 추가한다.
3. 표로 보고한다.
   | 기준 또는 항목 | 판정 (충족, 부분, 미충족) | 증거 (파일:줄, 테스트 이름, 명령과 결과 요지) |
4. 엣지 케이스 3개를 확인한다: 빈 입력, 잘못된 형식, 큰 입력이나 중복.
5. 보안 빠른 점검: 하드코딩된 비밀값, 입력 검증 누락, 쿼리 조합(인젝션), 과도한 개인정보 저장.
6. 문서와 코드 대조: README와 docs에 적은 기능이 실제 코드에 있는지.
7. 미충족과 부분 항목은 원인 가설과 다음 조치를 제안하고, 사소한 것 외에는 직접 고치지 말고 내 결정을 기다린다.
8. 결과 요약을 docs/STATUS.md에 한 줄 기록한다.
