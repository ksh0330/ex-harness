name: build-slice
description: 합의된 기능 또는 버그 수정 한 흐름을 구현하고 영향 범위에 맞게 검증한다. 기존 권한 안의 구현을 반복 승인으로 막지 않는다.
---

요청·수용 기준 중 검증 가능한 흐름 하나를 정한다. 기존 기술 스택과 사용자 변경을 먼저 확인한다.
중간 작업이면 수정 파일·접근·검증·위험을 짧게 설명한다. 작은 수정은 직접 처리한다.
이미 위임된 가역적 구현은 진행한다. 범위·데이터 삭제·외부 전송 등 새 권한이 필요할 때만 확인한다.
재현 가능한 로직 결함이면 실패 테스트부터 만든다. 단순 문구 수정에 구현을 복사한 테스트를 만들지 않는다.
요청 범위만 구현하고 관련 검증을 새로 실행한다. API·DB·공통 코어는 영향받는 경로까지 확인한다.

결과와 미검증을 구분한다. 실패한 코드를 자동 커밋하지 않는다.
커밋이 허용됐으면 검증된 이번 파일만 명시적으로 stage하고 [P단계] 메시지로 커밋한다.
큰 작업은 STATUS와 중요한 결정만 갱신한다. 요청 전체가 끝나지 않았으면 다음 slice를 계속한다.
같은 실패 2번이면 반복을 멈추고 가설 2개·각 확인 방법을 보고한다.
