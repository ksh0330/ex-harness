name: build-slice
description: P3 스캐폴딩부터 P6까지의 구현 루프. AGREEMENT의 항목 하나를 계획, 승인, 구현, 테스트, 커밋, 상태 기록 순으로 처리한다.
---

1. 대상 항목 하나를 정한다 (AGREEMENT의 P0 순서 우선). 20~30분 안에 끝날 크기로 자른다.
2. 계획을 3~7줄로 보여준다: 수정할 파일, 접근 방법, 검증 방법(어떤 테스트나 명령), 위험.
   P3 스캐폴딩이면: 실행되는 최소 골격, 테스트 1개, README 실행법, 포트 하나, 0.0.0.0 바인딩.
   P4 E2E v0이면: 입력부터 결과까지 핵심 흐름 하나가 끝까지 실제로 동작하는 것이 목표. 예쁘게 만들지 않는다.
3. 내 승인을 받으면 외과적으로 구현한다. 요청 범위 밖은 건드리지 않는다.
4. 테스트를 새로 실행하고 출력 요지를 보여준다. 웹이면 내가 브라우저에서 눌러볼 항목 2~3개를 알려준다.
5. 통과하면 "[P단계] 무엇을 했는지"로 커밋한다.
6. docs/STATUS.md 작업 로그에 한 줄: 시각, 항목, 결과, 커밋.
7. 중요한 기술 선택이 있었다면 docs/DECISIONS.md에 한 줄: 결정 / 이유 / 버린 대안.
8. 다음 항목을 제안하고 멈춘다.
