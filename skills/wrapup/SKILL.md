과제 지정 경로·파일·형식을 우선 확인한다. 새 기능보다 필수 수용 기준의 남은 결함을 처리한다.
README의 핵심 실행과 검증 명령을 새로 확인한다. 계속 실행할 서버는 사용자에게 명령을 안내하고 미확인 UI를 표시한다.
문서 주장을 실제 코드·테스트와 대조한다. 사용자 파일을 임시 파일로 오인해 삭제하지 않는다.
필수 검증 실패를 숨기거나 “준비 완료” 커밋을 만들지 않는다.
허용된 경우 검증된 이번 파일만 커밋한다. 시험에서는 push하지 않는다.
큰 작업은 최종 HANDOFF와 STATUS에 기준 커밋·검증·미완료·다음 행동을 남긴다.
코딩 종료 전에 `.harness/templates/FINAL_REVIEW.md` 또는 원본 `templates/FINAL_REVIEW.md`를 읽어 `docs/FINAL_REVIEW.md`(과제 지정 보고서가 있으면 그곳)를 작성·설명한다. 10개 항목은 결론→실제 코드/기록→이유→검증→한계 순서로 짧게 쓰고 1페이지 요약을 앞에 둔다. 장황한 개발 일지 복사 대신 중요한 커밋·파일·테스트·실패/수정·Reviewer 처리에 연결한다. AI 제안/추정과 사용자가 실제 수락·거절·수정한 판단을 분리한다.
구조와 데이터 흐름, 중요한 결정과 버린 대안, 실제 약점·영향·개선 방법을 설명한다.
설명이나 후속 질문의 전제가 실제 구현과 다르면 차이를 먼저 밝힌다. 추정·대체값·Mock을 실제 결과로 설명하지 않는다.
사용자의 직접 실습·수용·Cofa 확인이 남아 있으면 별도 표시한다. 서술형 제한이 시작되면 AI 사용을 안내하지 않는다.
제출 목록·실제 총용량·실행 파일과 README 일치·AI 협업/결정 기록을 확인한다. 과제 안 하네스 원본과 내부 .git, 임시 파일·의존성은 전체 폴더 제출에 포함될 수 있다. .gitignore는 제출 제외 보장이 아니며 사용자 파일을 임의 삭제하지 않는다.
완료: 필수 기준의 실행 증거·남은 한계·제출 대상이 정리됐으면 사용자에게 전달한다. 최종 제출/전송은 사용자가 수행하고, 미검증이나 필수 실패가 남으면 완료 범위를 제한해서 보고한다.
제출 직전 필수 충족·실제 테스트/브라우저·최종 Git/미커밋·파일/크기·보안/알고리즘 위험·보고서 경로·사용자 직접 확인/제출을 알린다. 보고서는 코딩 단계 설명용이다. 후속 서술형(문항당 5분·AI/복사 붙여넣기 금지)에 사용하도록 안내하거나 답변을 자동 입력하지 않는다.
