# 가상 과제 README: 수리 접수 현황 문의

연습용 합성 업무다. 실제 해커톤 문제를 추측·재현하지 않는다.

기존 `examples/web.py`·`web.html`·`fde/records.py`를 조사한다.
현장 담당자는 “접수 번호로 지금 상태를 알려 달라는 전화가 많다”고 말했다.
현재 앱은 등록·검색·상태 변경을 제공하지만 번호 하나를 조회하는 HTTP API는 없다.
처음부터 앱을 다시 만들지 않는다. 새 패키지·외부 서비스·로그인은 이번 연습 범위가 아니다.

## 명확히 주어진 요구

- 기존 등록·검색·상태 전환을 유지한다.
- 조회 결과가 없는 번호와 잘못된 입력을 구분한다.
- API를 만들면 같은 포트 8000을 사용하고 README에 실행·검증을 적는다.
- 결정은 PM에게 묻고 성공 수치·현재 전화 건수는 꾸미지 않는다.

## 아직 결정되지 않은 것

번호 단건 조회 API만 필요한가, 화면 검색까지 필요한가? 번호 노출 범위·개인정보를 어떻게 제한할까?
PM이 필수 범위·제외·수용 기준을 선택한다. 실무자 역할 카드는 SIMULATION 문서에 있다.
